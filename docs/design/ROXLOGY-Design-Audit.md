## 결과와 적용 범위

기록·훈련·레이스·크루 운영을 같은 디자인 체계로 연결한 개인용 리뉴얼 미리보기를 제작했습니다. 기존 노란색 브랜드 포인트를 유지하고, 밝은 배경과 명확한 표·카드·필터로 읽기 순서를 정리했습니다.

이 결과물은 별도 Sites에 게시한 **디자인 프로토타입**입니다. roxlogy.com의 운영 코드, 데이터베이스, 계정 권한, 회계 원장, 회원 상태는 수정하지 않았습니다. 원본 소스 저장소와 API를 연결한 실제 서비스 배포가 아닙니다.

브라우저에서 접근 가능한 주요 화면과 대표 상세·입력 화면을 분석했습니다. 모든 회원·모든 대회·모든 프로그램 주차를 전수 열람하거나, 삭제·납부·권한 변경·실제 기록 저장을 실행하지 않았습니다. 아래의 문제는 화면에서 관찰한 사실과 그에 따른 UX 판단이며, 서버 구현의 결함이나 보안 취약점을 확정한 보고서는 아닙니다.

## 2. 시각 체계

| 요소 | 제안 |
|---|---|
| 브랜드 | ROXLOGY 명칭과 노란색 유지. 중요한 행동·선택·기록 강조에 한정 |
| 배경 | 밝은 회색 작업 공간 + 흰색 패널 |
| 핵심 기록 | 짙은 차콜 패널에 완주 시간과 구간 비중 표시 |
| 상태 색상 | 완료는 녹색, 확인 필요는 노란색. 색과 함께 텍스트 라벨 사용 |
| 타이포그래피 | 한글 제목 24–30px, 주요 숫자 27–58px, 본문 중심 16px, 일반 라벨 14px, 보조 메타데이터 12–13px |
| 간격 | 패널 안쪽 20–24px, 패널 사이 20–24px. 목록은 행 간격과 구분선으로 정리 |
| 차트 | 장식보다 비교 목적을 우선. 숫자 표와 함께 제공 |
| 좁은 화면 | 사이드 메뉴를 접는 구조, 카드 1열, 긴 표는 패널 안에서 스크롤 |
| 접근성 | 입력 라벨, 키보드 포커스, 탭·선택·모달 기본 동작, 본문 이동 링크, 모션 감소 설정 대응 |

모바일 반응형 규칙은 구현했습니다. 이번 허용된 브라우저에는 화면 크기 변경 기능이 없어 실제 모바일 뷰포트의 시각 검증은 수행하지 못했습니다. 대비와 200% 확대까지 포함한 공식 접근성 적합성 검증을 완료한 것은 아닙니다.

## 3. 탐색 구조

- **나의 퍼포먼스:** 대시보드, 세션 기록, 레이스 결과, 목표와 계산기, 분석 리포트
- **트레이닝:** 주간 일정, 훈련 프로그램, 러닝 기록, 운동 라이브러리, PFT
- **커뮤니티:** 대회 일정, 크루, 리더보드, 피드
- **공통:** 검색, 알림, 프로필·설정
- **크루 내부:** 소개, 일정, 게시판, 리더보드, 멤버, 회계, 관리

개인 기록 탐색과 크루 운영을 분리하되, 오늘의 운동 → 운동 상세 → 완료 → 일정 반영, 대회 → 목표 설정, 크루 → 모임 응답, 회계 → 거래 추가가 이어지도록 구성했습니다.

## 5. 기록 데이터에서 확인한 구체적인 사례

### 서로 다른 디비전의 최고 기록

계정의 1:12:50은 릴레이 기록입니다. 프로 더블 Shenzhen 1:39:55와 총 시간만 비교해 개선·퇴보라고 말할 수 없습니다. 미리보기는 최고 기록에 디비전을 붙이고, 비교 페이지에서는 같은 디비전만 선택합니다.

같은 믹스 더블 기록인 Seoul 1:31:34와 Incheon 1:25:49의 차이는 **5분 45초 단축**입니다. 다만 코스·파트너·환경은 다를 수 있으므로 이 차이만으로 훈련 효과를 단정하지 않습니다.

### Shenzhen 구간 시간

| 항목 | 확인한 값 | 총 시간 대비 |
|---|---:|---:|
| 총 시간 | 1:39:55 | 100% |
| 런 합계 | 48:59 | 약 49.0% |
| 스테이션 합계 | 39:21 | 약 39.4% |
| 나머지 시간 | 11:35 | 약 11.6% |

런 48:59가 전체 1:39:55의 약 62%라는 원본 AI 설명은 위 시간과 일치하지 않습니다. 2,939초 ÷ 5,995초는 약 49.0%입니다. 미리보기는 계산된 비중을 사용합니다.

나머지 11:35는 총 시간에서 런·스테이션을 뺀 값입니다. 구간별 록스존 값이 보이지 않으므로 임의로 라운드별 값을 채우지 않았습니다.

공식 전체 순위 241/430과 공개 데이터 분포의 백분위는 모집단이 다릅니다. 원본 목록과 상세의 96%·95% 표기는 의미·기준일·분모를 함께 안내하는 것이 좋습니다. 수치가 다르다는 이유만으로 서버 계산 오류라고 단정하지 않습니다.

### 검토가 필요한 워치·PFT 데이터

워치 세션의 로잉 1,000m 0:29, 일부 짧은 1km 런, PFT `test`의 푸시업·월볼 0:02는 측정·입력 의미를 확인할 필요가 있습니다. 기록을 임의로 삭제하거나 실제 결과를 교정하지 않았습니다. 검토 상태를 도입하고, 검토 완료 전 최고 기록과 AI 분석 포함 여부를 사용자가 알 수 있도록 하는 것을 제안합니다.

## 8. 검증 결과와 한계

브라우저에서 대시보드, 레이스 목록, 회계 화면을 시각 확인했습니다. 프로그램·운동·PFT·대회·목표·계산기·피드·검색·알림·설정·관리자·모더레이션 등 주요 메뉴의 제목과 내용이 정상 표시되는지 확인했습니다.

실제로 확인한 대표 흐름:

| 확인 | 결과 |
|---|---|

데스크톱 브라우저의 주요 흐름을 검증한 결과입니다. 모든 입력 조합·권한 조합·모바일 기기·네트워크 오류를 전수 테스트한 것은 아닙니다. 실제 회원 권한, 데이터 저장, 결제, 기기 측정, 공식 HYROX 동기화, AI 응답은 연결되지 않았으므로 검증 대상이 아닙니다. 선택적으로 추가한 읽기 전용 WebMCP 인터페이스는 해당 브라우저에서 modelContext가 제공되지 않아 실행 검증을 할 수 없었습니다.

## 9. 실제 roxlogy.com 적용 순서

1. **원본 소스와 디자인 매핑:** 사용 중인 프레임워크·라우팅·컴포넌트 구조를 확인하고, 이번 공통 테마와 화면 구조를 기존 코드에 이식합니다.
2. **데이터 계약 정리:** 디비전, 기록 출처, 검토 상태, 테스트 여부, 공식 순위와 백분위의 분모를 구분합니다. 워치 세그먼트와 수동 입력 구간 모델을 매핑합니다.
3. **공통 UI 적용:** 탐색, 폼, 표, 탭, 모달, 빈 상태·오류 상태·저장 피드백을 먼저 통일합니다.
4. **핵심 흐름 연결:** 세션·훈련·레이스·목표·크루 일정 순서로 실제 API와 연결합니다. 기존 기능과 데이터가 유지되는지 확인합니다.
5. **회계·권한 연결:** 원본 장부의 개별 행과 감사 이력, 면제·조정·확정·되돌리기, 역할별 접근 범위를 연결합니다. 실제 금액 변경에는 기존 서버 검증과 권한을 유지합니다.
