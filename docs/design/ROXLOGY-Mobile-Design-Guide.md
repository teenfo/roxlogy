# ROXLOGY 모바일 디자인 가이드

문서 버전 1.3 · 2026-09-16 · 게시 버전 5

## 모바일 디자인 가이드

ROXLOGY · 모바일 스펙 1.3 · 2026.09.16
게시 버전 5의 반응형 코드와 향후 모바일 적용 기준을 함께 정리했습니다.

### 적용 범위와 상태

현재 구현은 접이식 사이드 메뉴, 카드·폼의 1열 전환, 2열 KPI, 표의 내부 스크롤을 포함합니다. 회계와 PFT 스태프에는 모바일 입력 16px·주요 컨트롤 최소48px·보조 컨트롤 최소44px를 적용했습니다. 나머지 화면의 같은 수치와 안전 영역 보완은 추가 적용할 권장 기준입니다.

| 뷰포트 구간 | 현재 반응형 규칙 | 주요 영향 |
|---|---|---|
| >1200px | 기본 데스크톱 | 카탈로그 3열, 폼 본문+310px 요약 |
| ≤1200px | 본문 28px 24px | 카탈로그 2열, 폼 요약 265px |
| ≤1050px | 공통 2열·폼 1열 | 요약 위치는 601~1050px에서 위쪽 |
| ≤1000px | 대시보드 1열 / KPI 2열 | 제목 27px |
| <768px | 모바일 Sheet 메뉴 | 기본 288px 폭; 메뉴 선택 시 닫기 |
| ≤600px | 본문 23px 16px / 상단바 60px | 카탈로그·폼 입력 1열; 패널 20px |
| 320~430px 검증 폭 | 추가 CSS 분기 자체는 없음 | 가이드의 검증 대상: 320, 360, 375, 390, 430px |

### 설계 원칙

첫 화면은 제목·핵심 수치·다음 행동을 보여줍니다. 길이가 긴 표와 필터 때문에 페이지 전체가 옆으로 밀리지 않게 합니다. 기능은 데스크톱과 같은 의미·명칭·주소를 사용합니다. 하단 탭 바와 바텀시트는 필수 구성으로 구현했습니다. 웹은 세션·훈련·레이스·크루·피드 5개, 네이티브 앱은 Watch를 포함한 6개입니다. 상세 규칙은 추가 장을 따릅니다.

390px 브라우저 내 미리보기에서 하단 탭과 훈련 바텀시트의 시각·동작을 확인했습니다. 실제 iOS/Android 기기·키보드·safe-area 검증은 미수행입니다. 뒤의 배치 예시는 권장 구조를 설명하는 벡터 와이어프레임이며 실제 사이트 캡처가 아닙니다.

## 01. 모바일 크기와 밀도

| 요소 | 현재 ≤600px | 적용 목표 |
|---|---|---|
| 본문 좌우 여백 | 16px | 16px 유지; 320px에서도 페이지 넘침 없음 |
| 상단바 | 높이 60px | 유지; 아이콘 조작 영역은 별도 확보 |
| 패널 | padding 20px / 반경 14px | 밀도 높은 목록에서는 행 구분을 유지 |
| 제목 | 25px / line-height 1.4 | 25px 유지; 긴 제목은 2줄 이상 허용 |
| 본문 | 16px / line-height 1.6 | 16px 유지 |
| 입력 글자 | 일반 14px / 회계·PFT 스태프 16px | 회계 외 화면도 16px 이상 권장 |
| 필드 라벨 | 14px | 유지; 필수·단위·예시를 가까이 배치 |
| 보조 정보 | 12~13px | 대비 충족; 금액·납부 상태 등 중요 정보는 14px 이상 |
| 주요 버튼 | 일반 42px / 회계·PFT 스태프 48px 이상 | 일반 화면도 높이 48px 이상 권장 |
| 일반 터치 영역 | 프리미티브별 33~42px 등 | 제품 기준 44×44px 이상 |
| KPI 숫자 | 21px / 2열 | 단위 줄바꿈 허용; 긴 금액은 1열 전환 검토 |
| 페이지 구역 간격 | 18~24px | 보통 20~24px; 관련 항목 안쪽은 8~12px |

### 폭 계산 예

390px 화면에서 본문 유효 폭은 390 - 16×2 = 358px입니다. 2열 KPI에 gap 12px를 적용하면 카드 폭은 173px입니다. 패딩과 긴 숫자까지 포함한 가독성을 확인합니다. 크기를 맞추기 위해 전체 UI를 scale로 축소하지 않습니다.

### 표면·색상

밝은 배경 #F5F6F8, 흰 패널, 노란 핵심 버튼, 차콜 기록 강조를 그대로 유지합니다. 햇빛이나 이동 중 사용을 고려해 #87919D 같은 옅은 보조 글자는 공통 --muted-foreground 등 대비를 충족하는 색으로 보완합니다.

## 02. 탐색·헤더·탭

| 영역 | 현재 동작 | 모바일 인계 규칙 |
|---|---|---|
| 메뉴 열기 | 상단 SidebarTrigger; <768px Sheet | 접근 가능한 이름 유지; 터치 영역 44px 이상 |
| 메뉴 폭 | 18rem (기본 288px) | 권장 max-width: calc(100vw - 32px) |
| 메뉴 내용 | 퍼포먼스·트레이닝·커뮤니티 | 현재 페이지·그룹을 유지; 메뉴 내부 세로 스크롤 |
| 메뉴 선택 | 일반 링크 이동 후 Sheet 닫기 | 뒤로 가기·딥 링크·새 문서의 제목을 확인 |
| 활성 메뉴 | 연노랑 배경·굵은 글자·왼쪽 선 | 색·굵기·텍스트로 현재 위치 확인 |
| 상단 오른쪽 | 미리보기 라벨·검색·알림 | 좁은 폭에서 겹치지 않게; 라벨 축약은 후속 결정 |
| 크루 탭 | 가로 스크롤, active 밑줄 3px | 현재 탭이 보이는 위치 유지; 스와이프만 강요하지 않음 |
| Segments | 높이 33px 탭 / 가로 스크롤 | 터치 영역 44px 확대 권장; 텍스트 줄바꿈보다 스크롤 |
| 본문 건너뛰기 | .rx-skip left:260px | 모바일에서는 left:16px, max-width 제한 보완 권장 |

### Sheet 접근성

Sheet의 기본 키보드·포커스 처리를 유지합니다. 열면 메뉴 안으로 포커스를 이동하고, 닫으면 열기 버튼으로 돌아가야 합니다. 닫기 동작을 배경 터치에만 의존하지 않고 명시적 버튼과 Escape를 확인합니다.

권장: 고정 상단바나 하단 작업 영역을 나중에 추가하면 실제 콘텐츠 높이와 스크롤 여백을 함께 확보합니다. 현재 상단바는 고정(sticky/fixed) 규칙이 없는 일반 문서 영역입니다.

## 03. 목록·카드·표

| 화면 종류 | 정보 우선순위 | 모바일 배치 |
|---|---|---|
| 세션·레이스 목록 | 기록명 → 시간 → 디비전 → 날짜·출처 | 현행 표 유지 시 내부 스크롤; 대표 요약 카드 전환은 추가 구현 |
| 프로그램 | 이름 → 상태 → 주차·운동 수 → 상세 | ≤600px 1열; 상세 이동 버튼 터치 영역 확대 |
| 운동 라이브러리 | 이름 → 분류·장비 → 상세 | 1열 카드; 긴 이름 줄바꿈 |
| 대회 | 도시·대회명 → 날짜 → 상세 | 1열; 표준 라벨과 대회 목표 연결 유지 |
| 멤버·리더보드 | 선수 → 디비전 → 기록 / 회원 구분 | 정보 행 전체의 읽기 순서 통일 |
| 회계 장부 | 날짜·거래명 → 수입/지출 → 금액 | 현행 표는 내부 스크롤; 금액과 상태를 생략하지 않음 |

### 표의 실제 동작

DataTable은 실제 table이고 컨테이너에 overflow:auto가 적용됩니다. 표 이름에는 min-width:160px가 있어 좁은 화면에서 표 내부 가로 스크롤이 발생할 수 있습니다. 표를 자동으로 카드로 바꾸는 코드는 현재 없습니다.

### 권장 스크롤 안내

표가 넘칠 때만 “좌우로 이동해 나머지 항목을 확인하세요” 안내를 표시합니다. 키보드로 스크롤 영역에 접근할 수 있게 이름과 포커스 방식을 검토합니다. 고정 열을 추가한다면 확대 시 다른 열과 버튼을 가리지 않는지 확인합니다.

### 필터 바

600px 이하에서는 검색이 한 줄 전체 폭을 차지하고 선택 필터가 다음 줄로 흐릅니다. 적용한 조건과 결과 수를 목록 가까이 표시하고 “전체”로 돌아가는 경로를 유지합니다. 여러 조건을 임의로 더보기 안에 숨기지 않습니다.

## 04. 입력·키보드·작업 버튼

현재 폼은 600px 이하에서 1열입니다. 601~1050px 구간에서 요약 패널은 입력 앞쪽, 600px 이하에서는 원래 문서 순서로 돌아갑니다. 모든 모바일 폭에서 요약이 상단에 고정되는 것은 아닙니다.

| 대상 | 모바일 적용 기준 | 현재 대비 |
|---|---|---|
| 일반 필드 | 라벨 → 48px 이상 입력 → 설명/오류 | 공통 42px·14px / 회계 48px·16px |
| 거리·금액 | 적절한 숫자 키보드, 단위 고정 | 기존 type/inputMode를 항목별 점검 |
| 시간 | m:ss 또는 h:mm:ss를 입력할 수 있는 키보드 | 숫자 전용 키보드로 콜론 입력을 막지 않음 |
| 구간 입력 | 8라운드 흐름 유지; 행별 합계 확인 | 현행 3구간 표는 내부 스크롤 |
| 오류 | 입력값 보존, 항목 가까운 설명, 첫 오류로 이동 | aria-invalid / aria-describedby 연결 보완 |
| 저장 | 누르면 진행 상태, 성공 후 결과 위치 확인 | 현재 로컬 데모 저장; 실 API 저장 중 상태 미구현 |
| 하단 작업 영역 | 추가 시 safe-area + 콘텐츠 여백 확보 | 현재 공통 고정 하단 저장 바 없음 |
| 키보드 열림 | 포커스된 필드·오류·저장 버튼 접근 가능 | 실기기 검증 필요 |

### 권장 입력 폼 구성

러닝 기록은 날짜·거리·시간·메모를 세로로 배치하고, 계산된 페이스를 저장 버튼 가까이 보여줍니다. 세션의 24개 구간은 첫 구현에서는 현행 표를 유지해 데이터 대응을 보존하고, 후속 개선 시 라운드별 입력 카드로 전환합니다. 두 구조가 서로 다른 값을 계산하지 않도록 같은 데이터 모델을 사용합니다.

### 미저장 데이터

현재 페이지 밖으로 이동하면 공유 상태에 저장하지 않은 입력은 사라질 수 있습니다. 운영 연결 시 변경 감지와 이탈 안내 또는 초안 복구를 결정합니다. 새로고침만으로 영구 저장이 되는 것처럼 안내하지 않습니다.

## 05. 차트·타이머·회계

| 영역 | 현재 구현 | 추가 적용·검증 |
|---|---|---|
| 레이스 Hero | ≤600px flex-wrap; 시간 50px | 320px에서도 제목·시간 충돌 없음; 긴 디비전 줄바꿈 |
| 런 차트 | ≤600px 높이 250px; 라벨 최종 12px | 8개 구간 값이 겹치면 내부 스크롤 또는 가로 행 차트 검토 |
| KPI | 2열 유지; 숫자 21px | 큰 금액·긴 단위가 2열을 깨면 해당 카드 1열 |
| PFT 타이머 | ≤600px 64px; 소수부 34px | 시작·정지·완료 구분; 주요 조작 48px 이상 |
| 주간 날짜 | 7열 유지; gap 5px | 375px 내 패널에서는 날짜 버튼 폭이 44px 미만일 수 있음 |
| 회비 요약 | flex-wrap, 모바일 padding18px | 금액·상태·인원을 별도 줄로; 금액 생략 없음 |
| 회계 탭 | 가로 스크롤 가능 | 장부/회비/요율의 활성 상태와 월 기준 명시 |
| 수입/지출 | 녹색/붉은색 금액 | 색과 함께 거래 유형을 텍스트로 표시 |

### 차트와 값의 동등성

큰 숫자로 총 시간을 보여주고 구간 값은 표 또는 명시적 텍스트로 함께 제공합니다. 차트를 터치해야만 값을 알 수 있는 방식은 피합니다. 런·스테이션·나머지의 정의를 유지하고 미확인 구간을 정밀 수치로 보이게 그리지 않습니다.

### 타이머의 한계

현재 PFT 측정은 로컬 타이머입니다. 앱 전환·백그라운드·기기 잠금에서 측정이 계속 정확한지 검증되지 않았습니다. 운영 측정 도구로 전환할 때는 경과 시간의 기준과 복구 정책을 별도로 설계하고 검증합니다.

주간 날짜 영역 권장: 7열을 강제로 좁히기보다 각 날짜 44px 이상의 가로 스크롤 행을 검토합니다. 날짜 선택 후 운동 목록 갱신과 선택된 날짜의 가시성을 유지합니다.

## 06. 배치 예시 - 홈과 기록

권장 모바일 배치 · 390 CSS px 기준 개념도 · 실제 브라우저 캡처 아님. 정보 우선순위와 터치 영역을 설명하며 현재 코드와 일부 차이가 있습니다.

배치 예시: dashboard, records (PDF에 벡터 도식 수록)

홈: 제목과 기록 추가 → 2열 KPI → 최근 레이스 → 오늘의 훈련 순서입니다. 기록 목록: 검색과 디비전 조건을 먼저 확인하고, 각 항목의 시간·날짜·상태를 함께 읽습니다.

기록 목록의 요약 카드 구조는 권장안입니다. 현재 구현은 표이며, 별도 카드 변환을 적용하기 전까지는 표 내부 스크롤을 사용합니다. 예시 숫자는 실제 최신 현황을 뜻하지 않습니다.

## 07. 배치 예시 - 입력과 훈련

권장 모바일 배치 · 390 CSS px 기준 개념도 · 실제 브라우저 캡처 아님. 입력 16px·48px, 날짜 터치 44px를 적용 목표로 사용합니다.

배치 예시: runform, training (PDF에 벡터 도식 수록)

러닝 입력: 날짜·거리·시간을 1열로 입력하고 예상 페이스를 확인한 다음 저장합니다. 훈련: 날짜 선택 → 진행률 → 운동별 체크 → 완료 순서로 조작합니다.

하단 저장·완료 버튼은 이 예시에서 문서 흐름 안에 배치했습니다. 기기 하단에 고정하는 안을 적용한다면 safe-area와 키보드 가림을 별도로 검증해야 합니다.

## 08. 배치 예시 - 크루와 회계

권장 모바일 배치 · 390 CSS px 기준 개념도 · 실제 브라우저 캡처 아님. 크루 탭과 월별 금액을 좁은 화면에서 확인하는 순서를 설명합니다.

배치 예시: crew, finance (PDF에 벡터 도식 수록)

크루: 짧은 헤더 → 가로 탭 → 다음 모임 → 참석 응답 → 공지입니다. 회계: 월 기준 → 요약 금액 → 장부·회비 탭 → 거래 유형과 금액을 함께 표시합니다.

회계 예시는 프로토타입의 집계 값을 사용합니다. 거래 카드 전환은 권장안이며 48px 주요 컨트롤은 11장에 명시한 회계 입력·버튼에 적용했습니다. 실제 원장 행·회원별 청구 데이터는 포함돼 있지 않습니다.

### 안전 영역과 키보드

고정 하단 영역을 추가할 때는 padding-bottom에 env(safe-area-inset-bottom)을 반영하고, 본문에도 같은 높이만큼 여백을 둡니다. 메뉴·모달 높이에는 동적 뷰포트와 내부 스크롤을 검토합니다. 소프트 키보드가 열렸을 때 포커스한 입력이 완전히 가려지지 않는지 실기기에서 확인합니다.

현재 공통 safe-area 보정·고정 하단 작업 바·화면별 카드 변환은 구현돼 있지 않습니다. docs/design-tokens.json의 recommendedMobile은 적용 목표이며 현재 app/globals.css 값을 덮어쓴 파일이 아닙니다.

## 11. 회계 모바일 적용 사항

이번 회계 수정은 데스크톱의 오른쪽 보조 패널이 좁은 화면에서도 접근 가능하도록 반응형 배치를 함께 적용했습니다. 앞의 모바일 배치 예시와 달리 이 페이지의 수치·배치 규칙은 현재 코드에 반영된 값입니다.

| 폭 | 장부 탭 순서 | 회비 탭 순서 |
|---|---|---|
| >1200px | 왼쪽 장부 / 오른쪽 거래 추가·지출 구성·계좌 | 왼쪽 수납 현황·대상자 / 오른쪽 계좌·회비 기준 |
| 1051~1200px | 같은 2단; 오른쪽290px | 같은 2단; 오른쪽290px |
| 601~1050px | 장부 → 거래 폼 전체 폭 → 지출 구성·계좌 2열 | 현황·대상자 → 계좌·회비 기준 2열 |
| ≤600px | 장부 → 거래 추가 → 지출 구성 → 계좌 | 현황 → 대상자 → 계좌 → 회비 기준 |

### 600px 이하에서 적용한 규칙

금액·거래 내용·메모·검색 입력은 16px입니다. 필드 입력·Select·주요 버튼은 최소48px, 보조 버튼·탭은 최소44px입니다. 날짜와 결제 필드 묶음은 1열로 전환합니다. 회비 요약의 3개 지표도 각각 한 줄로 배치해 긴 금액이 겹치지 않게 했습니다.

### 내용을 숨기지 않는 세로 전환

기초 잔액·누적 손익·미정산 순액·정산 잔액과 회비 기준은 모바일에서 제거되지 않습니다. 표는 기존처럼 내부 가로 스크롤을 유지합니다. 거래 폼은 문서 흐름 안에 있으므로 키보드 위에 별도 고정 버튼이 겹치지 않습니다.

### 남은 검수

실제 320~430px 기기의 날짜 입력·키보드·긴 거래명·음수 미정산액·필터 탭을 확인해야 합니다. 정산일이 있는 거래와 없는 거래를 각각 입력하고, 장부와 계좌 잔액이 정의된 수식대로 다르게 계산되는지 검증합니다. 현재 보완된 값의 적용 범위는 회계 화면이며 다른 도메인에는 자동 확대 적용되지 않습니다.

소스: app/globals.css의 .rx-finance-* / components/rox/finance.tsx. 웹 미리보기에서 장부·회비 탭 및 금액 반영을 확인했습니다. 모바일 실기기 시각 검증은 완료하지 않았습니다.

## 12. PFT 모바일 적용 사항

PFT 스태프와 라이브보드는 서로 다른 사용 목적에 맞춘 반응형 규칙을 사용합니다. 아래 수치는 게시 버전 5의 CSS에 구현돼 있습니다.

| 폭·화면 | 구현 배치 | 조작·읽기 규칙 |
|---|---|---|
| 스태프 ≤1050px | 선수 추가 → 웨이브 출발 | 선수 검색 결과2열; 선수 카드2열 |
| 스태프 ≤600px | 검색 결과와 선수 카드 모두1열 | 본문16px 여백, 카드20px 패딩 |
| 스태프 입력 | 16px / 최소48px | 검색 아이콘과 입력 내용의 간격 유지 |
| 스태프 버튼 | 주요 최소48px·출발52px·보조44px | 웨이브 배정 숫자 버튼 최소44px 폭 |
| 선수 카드 | 이름·상태 → 타이머32px → 6개 구간 | 현재 종목과 완료 버튼을 같은 카드에서 읽기 |
| 보드 ≤1100px | 참가자 전체 폭 → 측정·완주2열 | 기본3열에서 중간 폭2열로 전환 |
| 보드 ≤700px | 제목·4개 지표·종목3×2 | 측정 중 → 완주 순위 → 참가자 순서 |
| 보드 모바일 조작 | 전체화면·스태프 링크 최소44px 높이 | 항상 고정하지 않고 문서 흐름에서 스크롤 |
| 보드 숫자 | 측정30px·KPI22px·종목 목표20px | 표형 숫자; 보조 라벨12px |

### 현장 동작과 화면 수명

선수별 큰 완료 버튼으로 다음 종목을 기록하고, 실수는 직전 구간 되돌리기로 복구합니다. 레이스 종료는 진행 중 선수가 없을 때만 가능합니다. 로컬 기록은 같은 브라우저 프로필에서 유지되며, 휴대폰과 현장 모니터 사이의 기기 간 동기화는 실제 서버 연결 후 구현할 기능입니다.

### 추가 기기 검수

320·360·390·430px에서 긴 이름, 구간 분 수가 긴 값, 웨이브 버튼 줄바꿈, 화면 회전, iOS 전체화면 지원을 확인합니다. 라이브보드의 모바일 시각 순서는 CSS로 바뀌므로 키보드·스크린 리더 순서가 작업에 혼선을 주지 않는지 검수해야 합니다.

실제 모바일 기기·화면 폭 전환 검증은 완료하지 않았습니다. 데스크톱 브라우저에서는 스태프/보드의 별도 화면과 로컬 기록 반영을 확인했습니다. 다음 배치 예시는 읽기 순서를 설명하는 벡터 도식입니다.

390px 훈련 시트와 하단 웹5탭을 브라우저 내 실제 렌더로 확인했습니다. 앱6탭은 320px 구성 확인을 포함합니다. iOS Safari/Android Chrome의 가상 키보드, 홈 인디케이터, 텍스트 확대, VoiceOver/TalkBack은 실제 기기에서 추가 검증해야 합니다.

### 적용 상태

신규 화면은 입력16px·주요48px·보조44px를 기본으로 사용합니다. 이전 화면의 기존33~42px 필터 등은 이 보완으로 전부 교체하지 않았으며 이전 장의 권장 항목을 따릅니다. 모달/바텀시트 구현체는 shadcn이 아닌 원본 자체 Dialog입니다.
