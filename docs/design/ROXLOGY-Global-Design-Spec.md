# ROXLOGY 글로벌 디자인 스펙

문서 버전 1.3 · 2026-09-16 · 게시 버전 5

## 글로벌 디자인 스펙

ROXLOGY 디자인 리뉴얼 · 스펙 1.3 · 2026.09.16
게시 버전 5의 실제 소스와 스타일을 기준으로 정리했습니다.

### 디자인 방향

밝은 회색 작업 공간과 흰색 패널로 기록을 읽는 순서를 만들고, 노란색을 핵심 행동·선택 상태·기록 강조에 사용합니다. 핵심 레이스 결과는 짙은 차콜 영역으로 강조합니다. PFT 라이브보드는 현장 모니터용 독립 다크 화면이며, 일반 화면의 다크 모드 전환 기능을 의미하지 않습니다. 기록, 훈련, 크루 운영은 같은 탐색·폼·표 규칙을 공유합니다.

| 원칙 | 적용 규칙 |
|---|---|
| 성과보다 비교 조건을 먼저 | 디비전·출처·검토 상태를 시간과 함께 표시합니다. 다른 디비전의 총 시간을 성과 변화로 비교하지 않습니다. |
| 요약에서 행동으로 | 페이지 제목 → 요약 지표 → 필터/목록 → 상세 또는 입력 순서를 사용합니다. |
| 한 작업에 한 핵심 버튼 | 주요 작업에는 노란 버튼을 사용하고, 보조 작업에는 외곽선 또는 텍스트 버튼을 사용합니다. |
| 같은 의미에는 같은 표현 | 완료·검토·디비전·금액·날짜의 명칭과 숫자 형식을 화면 간에 통일합니다. |
| 기록에 근거를 남기기 | 관찰한 값, 계산한 값, 대표 예시를 구분하고 미확인 구간을 임의로 채우지 않습니다. |

### 문서의 구분

“구현”은 현재 코드에 들어 있는 값과 동작입니다. “권장”은 향후 실제 서비스 적용 시 맞출 기준입니다. CSS에 여러 선언이 있으면 뒤에 오는 규칙·구체적인 선택자·해당 미디어쿼리를 함께 적용합니다.

현재 결과물은 디자인 프로토타입입니다. 운영 roxlogy.com의 소스·DB 전체 복사본이 아니며, 실인증·권한·공식 기록 동기화·결제는 연결돼 있지 않습니다. 모바일 상세 규칙은 별도 모바일 디자인 가이드에 수록했습니다.

### 숫자·한글 조판

시간·페이스·금액에는 font-variant-numeric: tabular-nums를 사용합니다. 단위는 값과 분리해 읽되 의미상 함께 묶습니다. 프로그램 제목에는 word-break: keep-all이 적용돼 있습니다. 권장: 실제 사용할 한글 웹폰트를 라이선스 확인 후 고정하고, 일반 본문에는 음수 자간을 적용하지 않습니다.

공통 모바일 입력 컨트롤은 현재 14px이고, 회계와 PFT 스태프 화면에는 16px를 적용했습니다. 별도 모바일 가이드는 다른 화면에도 16px를 확장할 목표를 정의합니다.

### 레이아웃 템플릿

대시보드: 1.4fr + minmax(290px, 1fr), 1000px 이하 1열. 목록: PageHead → Stats(필요 시) → Toolbar → DataTable. 상세: Back → PageHead 또는 Hero → 구간·정보 Panel. 입력: minmax(0,1fr) + 310px 요약, 1050px 이하 1열. 카탈로그: 3열 → 1200px 이하 2열 → 600px 이하 1열.

권장 간격 체계: 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48px. 현재 코드에는 18·22·25·27px 등 조정값도 있으므로, 이 체계를 이미 전역 spacing 토큰으로 사용 중이라고 해석하지 않습니다.

## 05. 공통 컴포넌트 계약

구현 위치: components/rox/ui.tsx. 기반 인터랙션은 components/ui/의 shadcn·Radix 프리미티브를 사용합니다.

| 컴포넌트 | 입력 / 역할 | 디자인·동작 계약 |
|---|---|---|
| PageHead | title, description?, action? | 한 페이지의 제목과 주 행동을 함께 배치 |
| Panel | title?, action?, className | 흰 표면·경계·공통 안쪽 여백 |
| Go / Back | href, label 또는 children | Go는 버튼 모양 링크; Back은 상위 목록 이동 |
| Chip | tone, children | neutral / yellow / green / blue; 명시적 상태명 |
| Stats | [label, value, note][] | 값의 단위와 비교 조건을 note로 설명 |
| Find / Choice | value, onChange | 검색 입력과 선택 필터; 접근 가능한 이름 포함 |
| Segments | value, options, onChange | 현재 화면 안의 보기 전환; Tabs 기반 |
| NavTabs | items, path | 주소가 바뀌는 하위 화면; aria-current=page |
| DataTable | headers, rows | 실제 table 구조; 패널 내부 가로 스크롤 |
| Field / Hint | label, children | 항목별 라벨과 보조 설명 |
| Empty | title, description, action? | 비어 있는 이유와 다음 행동 |
| ProgressBar | value, label | 진행 값과 접근 가능한 이름 |

### 버튼 상태

기본 .rx-primary: 높이 42px, 좌우 패딩 17px, 글자 14px/700. 보조 버튼은 outline, 덜 중요한 작업은 ghost를 사용합니다. 프리미티브 기본 높이는 36px이고 패널 안에서는 최소 38px 규칙이 더해집니다. disabled는 투명도 50%와 pointer-events 비활성으로 표현합니다.

권장: 새 도메인 화면에서도 위 래퍼를 먼저 재사용합니다. 현재 라우트 이동은 components/rox/navigation.tsx의 일반 문서 링크를 사용합니다.

### 문구 기준

동작은 “기록 저장”, “거래 추가”, “측정 시작”처럼 결과를 알 수 있게 씁니다. 검토 상태는 “확인 필요”, 집계 대상은 “같은 디비전”으로 설명합니다. 토스트만으로 필수 오류 내용을 전달하지 않습니다.

권장: 삭제나 회계 확정처럼 되돌리기 어려운 동작을 운영 API에 연결할 때는 대상·영향·완료 상태를 명확히 표시합니다. 현재 시안에는 실제 회계 확정과 권한 변경 기능이 연결돼 있지 않습니다.

| 회계 단위 | 수입·지출·잔액·대상·납부 인원 분리 | 회원 수와 회비 대상 수는 다른 집계 |

### 검증 가능한 계산 예

Shenzhen: 총 1:39:55, 런 48:59(약 49.0%), 스테이션 39:21(약 39.4%), 나머지 11:35(약 11.6%). 나머지는 총 시간에서 확인된 두 합계를 뺀 계산값입니다. 구간별 록스존 원본 값으로 표현하지 않습니다.

2026년 9월 회계: 수입 390,001원 - 지출 136,750원 = 잔액 253,251원. 원본 장부 41건은 대표 3행으로 요약돼 있습니다. 개인별 회비 배분과 회원 행은 예시입니다.

이 수치는 분석 시점의 프로토타입 데이터이며 최신 경기·일정·재무 현황을 조회한 결과가 아닙니다. 데이터의 출처 설명은 data.ts, README.md 및 기존 화면 분석 보고서를 참고합니다.

## 10. 탐색과 상태의 수명

게시 버전 5는 일반 HTML 문서 이동을 사용합니다. 이전 게시용 번들에서 발생한 RSC 화면 전환 실패를 피하기 위한 현행 구현 계약입니다. 링크 이동을 기존 next/link 패턴으로 단순 치환하지 않습니다.

| 상태 종류 | 현재 수명 | 사용자가 알아야 할 결과 |
|---|---|---|
| 공유 프로토타입 상태 | records / runs / programs / board / transactions / completed | 같은 탭의 정상 내부 메뉴 이동 시 전달 |
| 전달 저장소 | sessionStorage의 1회성·목적지 일치 스냅샷 | 다음 문서가 읽은 뒤 삭제; 운영 DB 저장 아님 |
| 일반 공유 상태 새로고침 | 기본 예시 데이터로 초기화 | PFT 레이스 로컬 저장은 아래 별도 계약 |
| 페이지 안의 useState | 필터·타이머·좋아요·응답 등 해당 컴포넌트 | 다른 문서로 이동하면 일반적으로 초기화 |
| 일반 공유 상태 새 탭·다른 기기 | 공유 영속 저장 없음 | PFT 외에는 탭 간 자동 동기화하지 않음 |
| 폼 제출 후 이동 | React 업데이트 이후 상태 전달 | 새 목록에서 작성 결과 확인 |
| 외부 연동 | 원본 서비스 안내·링크 | 실제 기록 동기화·인증·결제·권한은 미연결 |

### PFT 레이스의 별도 저장

게시 버전 5의 PFT 레이스는 레이스 코드별 localStorage를 사용합니다. 새로고침 후에도 남고 같은 출처·같은 브라우저 프로필의 열린 탭에는 storage 이벤트로 반영됩니다. 다른 기기·계정·실제 서버로 동기화되지 않으며, 저장소가 차단되면 해당 탭의 메모리 상태만 사용합니다.

### 검증된 대표 흐름

화면 전환을 수정한 게시 버전 2의 파일에서 12개 주요 메뉴의 서로 다른 페이지 표시, 프로그램 이동, 크루 회계 이동을 확인했습니다. 러닝 5,000m·25:00 입력 후 목록에 5:00/km가 표시되고, 대시보드 왕복 후 기록이 유지되며, 새로고침 시 초기화되는 것을 확인했습니다.

### 운영 적용 시 바꿀 계약

실제 API 연결 시 목록·상세·저장 결과의 데이터 식별자를 통일하고, 서버 성공 여부·저장 중·실패·재시도 상태를 설계합니다. 프로토타입의 일회성 상태 전달을 회원 기록의 저장 장치로 사용하지 않습니다.

내부 구현: state.tsx / navigation.tsx. 게시 버전 3은 회계의 2단 구성과 보조 패널을 추가했습니다. 기초 잔액은 페이지 안에서만 유지되고 일반 문서 이동 후에는 초기화됩니다.

## 11. 가독성과 접근성 기준

현재 구현: html lang=ko, 필드 라벨, 검색·메뉴 아이콘의 접근 가능한 이름, 본문 건너뛰기 링크, 탭 프리미티브, 표의 헤더, 포커스 표시, reduced-motion 대응이 포함됩니다. 아래는 배포 전 검증 기준이며 전체 적합성 인증이 아닙니다.

| 대비 조합 | 계산한 비율 | 평가 |
|---|---|---|
| #25282D / #FFFFFF | 14.79:1 | 일반 텍스트 기준 4.5:1 이상 |
| #252B31 / #EFD126 | 9.41:1 | 주요 버튼 글자 |
| #69727F / #FFFFFF | 4.87:1 | 전역 보조 텍스트 |
| #87919D / #FFFFFF | 3.2:1 | 여러 보조 설명에서 사용; 일반 텍스트 기준 미달 |
| #FFFFFF / #EFCF20 | 1.54:1 | 노란 버튼에 흰 글자를 사용하지 않음 |

### 적용 기준

일반 텍스트 대비는 4.5:1 이상, 큰 텍스트는 3:1 이상을 목표로 합니다. 큰 텍스트의 기준은 약 24 CSS px 또는 굵은 약 18.7 CSS px입니다. 글자 크기만으로 대비 부족을 상쇄하지 않습니다. [1]

모바일 조작 영역은 제품 기준 44×44 CSS px 이상, 핵심 버튼 높이는 48px 이상을 권장합니다. WCAG 2.2 AA의 2.5.8은 24×24 CSS px 또는 간격 등 예외를 규정하므로, 44px 권장을 AA의 필수치로 표현하지 않습니다. [2]

320 CSS px 폭에서도 일반 콘텐츠의 양방향 스크롤이 발생하지 않도록 확인합니다. 2차원 표처럼 구조상 필요한 영역은 내부 스크롤로 제공합니다. 고정 UI를 추가하면 키보드 포커스가 완전히 가려지지 않아야 합니다. [3][4]

[1] W3C Contrast: https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html
[2] W3C Target size: https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html
[3] W3C Reflow: https://www.w3.org/WAI/WCAG22/Understanding/reflow.html
[4] W3C Focus: https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html

## 13. 회계의 2단 구성

게시 버전 3 · 첨부된 장부·회비 화면의 구조를 밝은 리뉴얼 테마에 적용했습니다. 구현 파일은 components/rox/finance.tsx이며 공통 크루 헤더와 탭은 유지합니다.

|---|---|---|
| 상단 | 4열 KPI; ≤1000px 2열 | 월 수입·지출·손익·크루 장부 잔액 |
| 전체 열 | minmax(0,1fr) + 320px; gap24px | ≤1200px 우측290px, gap20px |

### 금액 계산 계약

장부 잔액 = 기초 잔액 + 누적 손익. 정산 기준 잔액 = 장부 잔액 - 미정산 거래 순액. 정산일이 빈 신규 거래는 미정산으로 표시합니다. 기존 3개 집계 행은 원본 스냅샷의 정산 완료 상태로 간주합니다. “장부와 일치”는 예시 장부의 계산 일치이며 은행 실조회 결과가 아닙니다.

### 입력과 확인

유형·9월 거래일·분류·양의 정수 금액·거래 내용·결제 수단·선택 정산일·메모를 입력합니다. 거래를 추가하면 장부와 요약·지출 구성·정산 상태가 함께 갱신됩니다. 기초 잔액은 페이지 로컬 상태입니다.

브라우저 확인: 미정산 지출 10,000원 추가 → 월 지출146,750원·장부243,251원·정산 잔액253,251원. 기초 잔액100,000원 반영 → 장부343,251원·정산 잔액353,251원. 개발 미리보기에서 확인했고 TypeScript 검사와 게시용 빌드도 통과했습니다.

## 14. PFT 스태프 타이밍

### 정확도와 저장 범위

표시는 측정 중 m:ss.d, 완주·구간은 m:ss를 사용하며 표시 단위 아래는 버립니다. 내부 비교는 밀리초입니다. 소수점은 서버 계측 정확도를 뜻하지 않습니다. 동시에 여러 스태프 탭에서 수정하면 마지막 저장이 덮어쓰므로 운영 동시 수정에는 별도 서버 계약이 필요합니다.

구현: components/rox/pft-race.tsx / pft-race-state.ts. 저장 구조·레이스 코드·선수 ID·웨이브·구간 값을 검증합니다. 첨부의 0:22/0:23은 테스트 예시이며 세부 구간/소수값은 예시 데이터입니다.

### 권한 차단 5종

정지 계정은 상태 검토 후 재로그인, 크루 비로그인은 로그인, 모임 멤버 전용은 크루 가입, 회계 정회원 전용은 크루 상태 확인, 프로필 필수는 프로필 편집으로 안내합니다. 잠긴 정보 자체는 표시하지 않고 사유와 다음 행동을 제공합니다.

### 연결 시 지켜야 할 원본 인증 계약

네이티브 해시의 access/refresh token은 읽은 즉시 주소에서 제거하고 로그·분석·화면에 노출하지 않습니다. next는 동일 출처 내부 경로만 허용합니다. Google 인증·세션 설정·실제 정지/회원 검증은 기존 서버 로직에 연결해야 합니다.
