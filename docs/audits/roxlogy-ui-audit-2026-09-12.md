# Roxlogy 웹 UI 감사 — 2026-09-12

## 목적과 범위

Roxlogy 웹 UI의 브랜드 정합성, 정보 구조, 반응형 설계, 사용성 및 접근성을
평가하고 개선 우선순위를 정리한다. 이 감사에서는 제품 코드를 수정하지 않았다.

검토 범위는 다음과 같다.

- 브랜드 가이드와 전역 디자인 토큰
- 랜딩, 로그인, 회원가입, 이벤트, 크루, 예측, 다운로드 공개 경로
- 로그인 후 공통 레이아웃과 글로벌·모바일 내비게이션
- 대시보드와 데이터 시각화 컴포넌트
- 폼, 팝오버, 모달 및 모바일 바텀시트
- 정적 접근성 패턴과 로컬 SSR 응답

## 평가 방법과 한계

- 소스 기반 휴리스틱 감사와 정적 패턴 검색을 수행했다.
- 더미 공개 환경값으로 Next.js 개발 서버를 실행하고 주요 공개 경로의 SSR
  응답을 확인했다.
- `npm run check`로 타입 검사와 ESLint를 통과하는지 확인했다.
- 실행 환경의 npm 레지스트리 접근이 `403 Forbidden`으로 차단되어 Playwright를
  설치하지 못했다. 따라서 실제 데스크톱·모바일 스크린샷, 키보드 조작,
  Lighthouse 및 axe 검사는 이번 감사에 포함되지 않는다.
- 로컬 응답 시간에는 개발 서버 초기 컴파일과 유효하지 않은 외부 서비스 설정의
  영향이 있으므로 운영 성능 지표로 해석하지 않는다.

## 종합 평가

다크 팔레트, 카드 계층, 숫자 정렬, 공개·로그인 내비게이션 분리와 모바일 하단
탭 등 제품의 시각적 기반은 잘 구성되어 있다. 반면 기능 범위가 넓어지면서
키보드 포커스, 모달 의미 구조, 작은 보조 텍스트, 차트 대체 정보와 비동기 상태
안내가 공통 규칙 없이 누적되었다.

우선 해결할 문제는 다음과 같다.

1. 포커스 표시 및 모달·바텀시트 접근성
2. 차트의 텍스트·표 대체 정보
3. 10–11px 보조 텍스트와 낮은 대비 색상
4. 오류·성공·진행 상태의 보조기술 안내
5. 브랜드 가이드와 실제 앱 폰트의 불일치
6. 모바일 내비게이션에서 이동과 하위 메뉴 열기의 혼합

## 잘된 점

### 브랜드와 디자인 토큰

- Race Yellow, Track Blue, 배경, 전경 및 muted 색상이 전역 토큰으로 분리되어
  있다.
- 카드, 컨트롤, 보더 단계와 성공·오류·정보 상태색도 별도 토큰을 갖는다.
- 기록, 날짜 및 금액에 사용할 수 있는 tabular 숫자 클래스가 제공된다.

### 정보 구조와 반응형 기반

- 비로그인 사용자에게 실제로 접근 가능한 공개 메뉴만 보여 준다.
- 로그인 상태에서는 데스크톱 글로벌 내비게이션과 모바일 하단 탭을 구분한다.
- 앱 본문에 모바일 탭바를 피하기 위한 하단 여백이 적용되어 있다.
- 모바일 탭은 최소 높이 44px을 사용한다.
- 문서 `lang`이 현재 로케일에 맞춰 설정된다.
- 랜딩 티커는 `prefers-reduced-motion`을 존중한다.

### 랜딩 경험

- 핵심 메시지, 설명, 회원가입·로그인 CTA와 공개 도구 링크의 순서가 명확하다.
- 분석 데모 카드에는 샘플 데이터임을 표시한다.
- 모바일에서 주요 CTA를 전체 너비로 확장한다.

## 상세 개선 포인트

### P0. 키보드 포커스 표시를 전역에서 보장한다

정적 검색에서 `outline-none`은 75회, `focus-visible`은 0회 확인되었다. 다수
입력은 기본 아웃라인을 제거한 뒤 포커스 상태를 얇은 보더 색상 변화로만
표현한다. 다크 배경에서는 현재 위치를 놓치기 쉽다.

권장 사항:

- 링크, 버튼, 입력, 카드 링크에 공통 `:focus-visible` 링을 적용한다.
- 최소 2px 링과 배경에서 분리되는 offset을 사용한다.
- 스크롤 컨테이너와 모달 안에서도 포커스 링이 잘리지 않게 한다.
- 포커스 상태를 색상 하나나 보더 변화 하나에만 의존하지 않는다.

### P0. 모달과 바텀시트를 공통 접근성 컴포넌트로 만든다

여러 전체 화면 오버레이가 일반 `div`로 렌더되며 `role="dialog"`,
`aria-modal`, 제목 연결 및 포커스 트랩이 일부 구현에만 존재한다. 모바일
바텀시트는 Escape로 닫을 수 있지만 열린 뒤 포커스 이동과 닫힌 뒤 트리거로의
복귀가 없다.

공통 Dialog/BottomSheet가 다음을 보장해야 한다.

- `role="dialog"`, `aria-modal="true"`, `aria-labelledby`
- 열릴 때 첫 유효 컨트롤로 포커스 이동
- Tab 포커스 트랩과 Escape 닫기
- 닫을 때 트리거로 포커스 복귀
- 배경 스크롤 잠금과 배경 콘텐츠 `inert` 처리
- 명시적인 닫기 버튼

### P1. 차트에 비시각적 대체 정보를 제공한다

스플릿·추이 차트는 축, 색상 및 hover 툴팁에 크게 의존한다. 시간 구성
스택바는 각 조각의 값을 `title` 속성으로 제공하는데, 이는 터치나 키보드에서
안정적인 전달 수단이 아니다.

권장 사항:

- 차트마다 한 문장으로 핵심 결론을 먼저 제공한다.
- 데이터 표 보기 토글을 제공한다.
- 빠름·느림과 시리즈를 색상뿐 아니라 라벨, 선 모양 또는 마커로 구분한다.
- 터치에서 포인트를 선택하고 값을 고정할 수 있게 한다.
- 10px 축 라벨은 12px 이상으로 검토한다.

### P1. 10–11px 텍스트 사용을 제한한다

`text-[10px]` 또는 `text-[11px]` 사용이 192회 확인되었다. 짧은 장식 배지에는
쓸 수 있지만 모바일 탭, 차트 축, 폼 도움말 및 의미 있는 상태에는 너무 작다.

권장 사항:

- 본문과 설명은 최소 14px을 기준으로 한다.
- 모바일 탭과 차트 축은 12px 이상을 검토한다.
- 10px은 비핵심 장식 배지에만 제한한다.
- 16×16px 도움말 아이콘의 실제 터치 영역을 40–44px 이상으로 확장한다.

### P1. 비동기 상태를 보조기술에 알린다

오류와 성공 메시지 대부분이 일반 문단으로 추가된다. 전체 앱에서
`aria-live`, `role="status"`, `role="alert"` 사용은 매우 제한적이다.

권장 사항:

- 제출 오류에는 `role="alert"`를 사용한다.
- 저장·복사 성공과 진행 상태에는 `role="status"` 또는
  `aria-live="polite"`를 사용한다.
- 필드 오류를 `aria-describedby`로 해당 입력과 연결한다.
- 제출 실패 시 첫 오류 또는 오류 요약으로 포커스를 이동한다.

### P1. UI 폰트 정책을 확정한다

브랜드 가이드는 Archivo/Archivo Black과 IBM Plex Sans KR을 지정하지만 실제
웹 앱의 전역 본문은 Pretendard 계열을 우선한다.

다음 중 하나를 명확히 결정한다.

1. 브랜드 가이드대로 헤딩·워드마크에는 Archivo Black, 한글 본문에는 IBM Plex
   Sans KR을 적용한다.
2. UI 가독성과 성능을 위해 Pretendard를 유지하되 브랜드 가이드에 UI 예외와
   헤딩·본문·수치별 서체 역할을 명시한다.

### P1. 작은 텍스트의 대비를 높인다

기본 muted `#9A9A96`은 `#141414` 위에서 약 6.52:1이지만 일부 컴포넌트의
임의 색상은 더 낮다.

- `#555555` / `#141414`: 약 2.47:1
- `#777777` / `#141414`: 약 4.11:1
- `#8A7A2A` / `#141414`: 약 4.30:1
- `#FFD500` / `#141414`: 약 12.96:1

임의 hex를 `muted-strong`, `disabled`, `placeholder` 등의 시맨틱 토큰으로
흡수하고, 특히 10–11px 텍스트에는 더 높은 대비를 적용한다.

### P2. 모바일 탭의 동작을 예측 가능하게 한다

하위 메뉴가 없는 탭은 즉시 이동하지만 훈련·레이스 탭은 목적지로 이동하지 않고
바텀시트를 연다. 같은 형태가 서로 다른 행동을 수행하므로 처음 사용하는 사람은
동작을 예측하기 어렵다.

권장 사항:

- 하위 메뉴가 있음을 chevron이나 별도 표식으로 보여 준다.
- `aria-expanded`, `aria-haspopup`, `aria-controls`를 적용한다.
- 탭이 항상 대표 화면으로 이동할지, 두 번째 탭에서 메뉴를 열지 정책을 정한다.
- 마지막으로 사용한 하위 화면을 기억하는 방안을 검토한다.

### P2. 문자 기호 아이콘을 통일한다

내비게이션이 `▶`, `≡`, `⚑`, `∞`, `◫`, `◔` 같은 문자 기호에 의존한다.
운영체제와 폰트에 따라 굵기, 정렬 및 이모지 렌더링이 달라질 수 있다.

- 단일 SVG 아이콘 세트를 사용한다.
- 선 굵기, viewBox 및 optical size를 통일한다.
- 선택 상태는 색상뿐 아니라 배경·형태로도 표현한다.
- 아이콘 버튼의 접근 가능한 이름은 유지한다.

### P2. 데이터 의존 화면의 대기 경험을 설계한다

로컬 개발 환경에서 공개 경로의 SSR 응답을 확인했으나 일부 데이터 의존 경로는
더미 외부 서비스 설정 때문에 오래 대기했다. 운영 성능 수치는 아니지만 느린
네트워크에 대한 UI 대비가 필요하다.

- 경로별 `loading.tsx`와 실제 레이아웃 형태의 스켈레톤을 제공한다.
- 핵심 설명과 입력 폼은 부가 데이터보다 먼저 보여 준다.
- 데이터 블록을 Suspense 경계로 분리한다.
- 빈 상태와 로딩 상태를 명확히 구분한다.
- 사용자 액션 후 즉시 진행 피드백을 제공한다.

## 화면별 권장 사항

### 랜딩

- 현재 가치 제안과 CTA 계층은 유지한다.
- 작은 샘플 데이터 배지를 키운다.
- 데이터 구성 막대에 접근 가능한 텍스트 설명을 추가한다.
- 모션 감소 환경에서도 크루 목록을 충분히 탐색할 수 있게 한다.
- 마케팅 헤딩의 브랜드 폰트 적용 여부를 확정한다.

### 인증

- 오류 영역을 live region으로 만든다.
- 비밀번호 조건을 제출 전에 보여 준다.
- 표시 이름 누락으로 가입 버튼이 비활성화되는 이유를 인접 문구로 설명한다.
- 비밀번호 표시 버튼과 소셜 로그인에 명확한 포커스 스타일을 적용한다.

### 대시보드

- 첫 화면에는 오늘 할 일과 최근 성과를 우선 배치한다.
- 상세 분석은 접거나 별도 화면으로 연결한다.
- 빈 카드가 반복되지 않도록 통합 온보딩을 제공한다.
- 각 차트 위에 한 줄 해석을 제공한다.
- 개인 일정과 크루 일정의 소속을 시각적으로 구분한다.

### 모바일 앱 셸

- 360px 화면과 WebView의 6개 탭 상태에서 실제 터치 및 문구 잘림을 검증한다.
- 현재 위치를 색상 외에도 형태와 의미 속성으로 표시한다.
- 바텀시트를 공통 접근성 컴포넌트로 교체한다.
- 네이티브 워치 탭과 웹 메뉴의 아이콘 스타일을 통일한다.
