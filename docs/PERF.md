## 1. 왜 모든 라우트가 동적(`ƒ`)이었나 — 그리고 어떻게 풀었나

**(해결됨 — 아래 "해결됨" 절 참조. 원인 분석은 기록으로 남긴다.)**

빌드 출력에서 80여 개 라우트가 전부 `ƒ` 이고 정적인 것은
`/robots.txt`, `/sitemap.xml`, `/manifest.webmanifest` 셋뿐이었다.

**원인은 파일 하나가 아니다. 쿠키 기반 i18n 이다.**

- `lib/i18n/index.ts:40` 의 `getT()` 가 `await cookies()` 로 `NEXT_LOCALE` 을 읽는다
- **`app/**/page.tsx` 68개 중 66개가 `getT()` 를 직접 호출**한다 (55개는 추가로
  Supabase 서버 클라이언트도 만든다 — 이것도 `cookies()` 를 쓴다)
- `app/not-found.tsx` 도 `getT()` 를 부른다. 그래서 404조차 동적이다
- `app/layout.tsx` 의 `getT()` 는 그중 하나일 뿐이다

### 실험으로 확인한 것

루트 레이아웃의 `getT()` 호출만 제거하고 빌드하면 **정적으로 바뀌는 라우트가 0개**다.
각 페이지가 독립적으로 쿠키를 읽기 때문에 레이아웃만 고쳐서는 아무 일도 일어나지 않는다.

```
before static: /manifest.webmanifest, /robots.txt, /sitemap.xml
after  static: /manifest.webmanifest, /robots.txt, /sitemap.xml   ← 변화 없음
```

### 해결됨 — 로케일을 Suspense 안으로 옮겼다 (2026-09-13)

한동안 "i18n 구조를 통째로 바꾸지 않으면 불가능"으로 판단했으나, 세 번째 길이 있었다.

`<html lang>` 만 셸에서 기본 로케일로 내보내고, **로케일 해석을 `<Suspense>` 안의
서버 컴포넌트(`components/locale-boundary.tsx`)로 내린다.** 거기서는 쿠키를 읽어도
셸이 정적으로 남고, 서버·클라이언트가 처음부터 같은 사전을 본다.

각 페이지의 `getT()` 는 그대로다 — 서버 렌더 텍스트는 계속 사용자 언어로 나온다.
URL 도 바뀌지 않는다. 로케일 경로 분리(`/ko`, `/en`)는 **하지 않았고, 필요도 없어졌다.**

> ⚠️ 처음에는 셸에서 기본 사전을 주고 브라우저에서 바꾸게 했는데, 셸이 먼저
> 하이드레이션돼 언어를 바꾼 뒤 스트리밍된 본문이 옛 언어 HTML 로 하이드레이션되면서
> 텍스트가 어긋났다(React #418, 프로덕션 빌드에서만 재현). 위 구조가 그 수정이다.

## 3. 하지 않은 것과 이유

- **공개 페이지를 완전 정적(`○`)으로** — 아직이다. PPR 로 셸은 엣지에서 나가지만 본문은
  여전히 스트리밍된다. 완전 정적이 되려면 그 페이지에서 `getT()`·세션 읽기·
  `unstable_cache`·`new Date()` 를 모두 걷어야 한다(§4 참조)
- **미들웨어 matcher 대폭 축소** — `/`, `/crews`, `/predict`, `/board/*` 는 뺄 수 없다.
  미들웨어가 만료된 액세스 토큰을 갱신해 응답 쿠키에 실어 주는데, 서버 컴포넌트는
  쿠키를 쓸 수 없어서 빼면 토큰이 만료된 로그인 사용자가 비로그인으로 보인다.
  세션을 아예 읽지 않는 `/events`·`/download` 만 뺐다
- **로케일 경로 분리(`/ko`, `/en`)** — 필요 없어졌다. §1 의 방법으로 URL 을 그대로 두고
  같은 목적을 달성했다
- **FK 인덱스 누락·미사용 인덱스** — 실제 쿼리 패턴이 보인 뒤에 판단한다

## 4. PPR(`cacheComponents`)을 실제로 켜 본 결과

Next 16 에서 `experimental.ppr` 은 **`cacheComponents` 로 통합**됐다
(`experimental: { ppr: 'incremental' }` 는 빌드 에러 — 플래그가 없어진 게 아니라 이름이 바뀐 것).

`cacheComponents: true` 로 빌드해 보면 두 단계에서 막힌다:

1. `app/board/[code]/page.tsx` 의 `export const dynamic = "force-dynamic"` 과 호환되지 않는다
   (`Route segment config "dynamic" is not compatible`)
2. 그걸 빼면 다음은 프리렌더에서 터진다 —
   `Route "/admin/content": Uncached data was accessed outside of <Suspense>`

**핵심: `cacheComponents` 는 라우트별 옵트인이 아니라 전역이다.** 예전 `ppr: 'incremental'`
이 담당하던 "적용할 라우트에만 켜기"가 사라져서, 켜는 순간 **68개 페이지 전부가**
캐시되지 않는 데이터 접근을 `<Suspense>` 로 감싸야 한다. 한두 라우트만 시험 삼아
적용하는 길이 없다.

즉 캐싱으로 가는 길은 어느 쪽을 골라도 앱 전체를 건드리는 작업이다.

## 5. 이미 확인했고 원인이 아닌 것 — Supabase JWT 서명키

`proxy.ts` 의 `getClaims()` 가 요청마다 Auth 서버로 왕복하는 것 아니냐는 의심이 있었으나
**2026-09-13 확인 결과 아니다. 다시 조사하지 말 것.**

JWKS(`alg: ES256`, `kty: EC`, P-256) · 실제 발급 토큰 헤더 · 대시보드 JWT Keys 3중 확인으로
**비대칭 서명 전환이 이미 끝나 있다.** `getClaims()` 는 JWKS 로컬 검증 경로를 타고 요청당
Auth 왕복은 없다. §0 의 225ms 는 대부분 Next.js 함수 실행 자체다.

레거시 HS256 키가 `Previously used keys` 에 남아 있지만 성능과는 무관하다(위생 차원의
정리 항목이고, 인증에 손대는 변경이라 사람 승인이 필요하다).

## 5.6 프리페치 0건에 대한 단서 — 아직 확정되지 않았다

`prefetch={false}` 는 Next 16 에서 **hover·touch 프리페치까지 끈다**
(`dist/client/app-dir/link.js` 의 `prefetchEnabled = prefetchProp !== false` 와
onMouseEnter·onTouchStart 의 early return). 이건 확인됐고 `RowLink` 로 고쳤다.

다만 **0건은 변경 내역만으로 설명되지 않는다.** `/dashboard` 에서 바꾼 링크는 3곳뿐이고
네비게이션 바·탭바는 손대지 않아 기본 프리페치가 그대로다. `loading.tsx` 도 있어서
동적 라우트도 프리페치 대상이며, App Router 의 프리페치에는 saveData·2g 게이팅이 없다
(Pages Router 에만 있다). 즉 네비게이션 링크는 계속 프리페치돼야 정상이다.

그러므로 0건은 둘 중 하나다:

1. 자동화 브라우저 환경 때문에 프리페치가 통째로 발생하지 않았다 (측정 아티팩트)
2. 실제로 무언가가 앱 전역의 프리페치를 막고 있다

**실제 사람의 브라우저에서 다시 재기 전까지 "목표 달성"으로 결론 내지 말 것.**
1번이면 실제 값은 29에서 3~4건 줄어든 정도일 수 있고, 그러면 캐싱 재판단의 전제가 달라진다.

## 7. 새 기능을 개발할 때 (체크리스트)

이 앱의 비용 구조는 단순하다. **모든 라우트가 동적이라(§1) 페이지 요청 하나가
도쿄 함수를 깨우고, 그 안에서 도는 Supabase 왕복 횟수가 응답 시간을 정한다.**
함수 실행 바닥값이 이미 약 225ms 다(§0). 여기에 무엇을 얹느냐가 전부다.

### 서버 컴포넌트 — 왕복 횟수가 전부다

- **독립적인 조회는 반드시 `Promise.all`.** 순차 `await` 하나가 도쿄 왕복 하나다.
  `(app)` 페이지는 이미 미들웨어 + 레이아웃(유저·프로필·알림 수)으로 왕복을 쓰고
  시작하므로, 페이지가 3개를 순차로 더 돌면 그대로 더해진다
  (2026-09-13 실제: WOD 화면에서 독립 조회 2개를 순차로 뒀다가 묶었다)
- **목록에서 행마다 조회하지 말 것(N+1).** id 를 모아 `.in()` 한 번으로 받고
  `Map` 으로 맞춘다. 이 레포는 대부분 그렇게 돼 있다
- `select("*")` 대신 쓸 컬럼만 적는다. `erg_samples.samples` 같은 JSONB 를 무심코
  끌어오면 페이로드가 통째로 넘어온다
- 개수만 필요하면 `select("id", { count: "exact", head: true })` — 행을 실어 나르지 않는다

### 링크

- **목록의 행 링크는 `<Link>` 가 아니라 `RowLink`**(`components/row-link.tsx`).
  뷰포트 프리페치를 끄고 hover·touch 때만 받는다. 행이 20개 깔리는 화면에서
  그냥 `<Link>` 를 쓰면 프리페치 20건이 전부 함수 호출이 된다
- **`prefetch={false}` 를 직접 쓰지 말 것.** Next 16 에서는 hover·touch 프리페치까지
  꺼진다(§5.6). 뷰포트만 끄고 싶으면 `RowLink` 를 쓴다
- 네비게이션 바·탭바처럼 실제로 자주 눌리는 소수 링크는 기본 프리페치를 그대로 둔다

### 새 라우트

- **`loading.tsx` 를 같이 만든다.** 지금 46개 `(app)` 라우트 중 7개에만 있다.
  없으면 프리페치가 미리 받아 둘 것이 없고, 스트리밍 셸도 안 나와 흰 화면이 길어진다
- `(app)` 아래에 폴더를 추가하면 **`web/proxy.ts` 의 `PROTECTED_PREFIXES` 에도 추가**한다
  (빠뜨리면 보호는 되지만 로그인 후 원래 화면으로 못 돌아간다 — 파일 주석 참조)
- 세션을 전혀 읽지 않는 공개 페이지라면 미들웨어 matcher 에서 뺄 수 있는지 본다

### 클라이언트 번들

- 현재 압축 기준 339KB / 최대 청크 105KB. **지금 병목은 아니지만** 무거운 라이브러리를
  새로 들일 때는 한 번 재 본다
- 차트·에디터처럼 첫 화면에 필요 없는 것은 `dynamic(() => import(...))` 으로 미룬다
- 서버에서 끝낼 수 있는 계산을 클라이언트로 내리지 않는다

### DB

- **RLS 정책의 `auth.uid()`·`is_admin()` 등은 `(select ...)` 로 감쌀 것.**
  감싸지 않으면 행마다 평가된다(2026-09-13 에 5건을 고쳤다 — 새 테이블마다 재발한다)
- 정책은 명령별로 하나씩. `for all` 은 SELECT 분기를 하나 더 만든다 (CLAUDE.md)
- **인덱스를 만들기 전에 이미 있는지 본다.** 이름만 다른 동일 인덱스가 두 개 생겨 있었다
  (`notifications`, 마이그레이션 두 개가 각각 만들었다). 쓰기마다 두 번 갱신된다
- 새 인덱스는 실제 쿼리 패턴이 생긴 뒤에 만든다. 미리 깔아 두면 쓰기만 느려진다

### Realtime·폴링

- PFT 보드가 Realtime + 5초 폴링을 쓴다. 이런 것을 새로 붙일 때는 **화면을 벗어나면
  반드시 정리**하고, 폴링 간격이 실제로 필요한 값인지 따진다

### 측정

- 성능이 걸리는 변경을 했으면 `docs/PERF_MEASURE.md` 의 절차로 재고 §5.5 표를 갱신한다
- 응답 시간은 **서울 브라우저**로 잰다. 해외 경유 `curl` 은 타이밍에 쓸 수 없다

## 8. 건드리지 말 것

- 함수 리전 `hnd1`(도쿄) — Supabase 가 `ap-northeast-1` 이라 서울로 옮기면 DB 왕복마다
  지연이 더 붙는다. 정본은 `web/vercel.json`
- 정적 자산 캐시 헤더 (`public, max-age=31536000, immutable`) — 이미 엣지 HIT 확인됨
- 압축 설정 — Brotli 정상 (130KB → 37KB)
- 성능을 이유로 Pro 플랜 전환 — 원인이 컴퓨트가 아니다
- **Supabase JWT 서명키를 성능 목적으로 건드리지 말 것** — §5 에 확인 근거가 있다
