## 1. 적용 범위와 문서 읽는 법

**목표는 원본 ROXLOGY 브랜드와 실제 서비스 동작을 유지하면서, 모든 화면에서 정보의 순서·조작 방법·상태 표시를 일관되게 만드는 것이다.** 대시보드에만 적용하지 않는다. 공개 페이지, 인증, 생성·수정·상세, 운영 도구, 모바일 WebView, 공유물, 오류·로딩·권한 분기까지 포함한다.

문서에서 다음 세 가지를 구분한다.

| 표현 | 의미 |
| --- | --- |
| 현재 구현 | 위 기준 커밋의 코드에서 확인한 구조·값·분기. 브라우저 검증 완료를 의미하지 않는다. |
| 준수 기준 | 이후 디자인·개발·검수에서 충족할 요구사항. 기존 화면도 이 기준으로 확인한다. |
| 후속 보완 / 미검증 | 코드와 기준의 차이 또는 아직 실환경에서 확인하지 못한 내용. 완료로 처리하지 않는다. |

사용자가 확정한 변경이 우선한다. 브랜드 원본은 `brand/`이고, 웹 UI 서체 예외와 밝은 작업 공간은 현재 앱의 적용 기준이다. 예전 프로토타입의 임시 로고·한국어 전용 카피·목업 데이터·shadcn 컴포넌트는 구현 근거로 사용하지 않는다. 과거 모바일 탭바 보류 문구는 현행 기준이 아니다.

이번 작업은 사용자가 요청한 별도 브랜치에서 계속한다. 저장소의 일반적인 main 직접 작업 규칙을 이유로 이 변경을 main에 옮기지 않는다.

## 2. 브랜드 자산과 콘텐츠

### 2.1 원본 자산 대치 규칙

| 용도 | 원본 / 웹 배포 파일 | 적용 규칙 |
| --- | --- | --- |
| 다크 바탕의 마크 | `brand/roxlogy-mark.svg` / `web/public/roxlogy-mark.svg` | 인증 브랜드 영역·PFT 보드·다크 기록지·OG |
| 밝은 바탕의 마크 | `brand/roxlogy-mark-inverse.svg` / `web/public/roxlogy-mark-inverse.svg` | 앱 내비게이션·랜딩 헤더·인증 폼·404·밝은 기록지 |
| 앱 아이콘 | `brand/roxlogy-appicon.svg` / `web/public/roxlogy-appicon.svg` | 앱 설치·다운로드 등 앱 아이콘 자리. 일반 UI 아이콘과 구분 |
| 워치 자산 | `brand/roxlogy-watchface.svg` | 워치 브랜드 자료. 웹 Watch 탭은 기존 `NavIcon` 사용 |
| 워드마크 | Archivo Black로 `ROXLOGY` | 대문자·기존 마크와 조합. 앱 제목을 다른 브랜드명으로 바꾸지 않음 |
| 웹 브랜드 폰트 | `web/public/fonts/ArchivoBlack-Regular.ttf` | 기존 `web/assets/og/ArchivoBlack-Regular.ttf`와 동일한 자산·라이선스 사용 |
| 앱 UI 폰트 | `web/public/fonts/pretendard/`, `web/app/fonts.css` | 자체 호스팅 동적 서브셋 유지. 본문·표·컨트롤·숫자·앱 섹션 제목 |
| OG 한글 폰트 | `web/assets/og/IBMPlexSansKR-Bold.ttf` | 서버 이미지 렌더용. 일반 페이지의 폰트로 추가 전송하지 않음 |

준수 기준:

- 마크의 옐로 외곽 링은 8조각, 블루 내부 링은 연속, 중심은 원본 R이다. SVG 경로를 다시 그리거나 CSS 원·문자 R로 흉내 내지 않는다.
- 종횡비를 유지하고 원본 내부 여백을 자르지 않는다. 배경별 원본을 선택하며 임의 색상 필터로 반전하지 않는다.
- 브랜드 가이드에는 20px 이하 R 단독 사용 규칙이 있다. 실제 사용 가능한 승인 자산이 없는 경우 새 R을 그리지 말고 전체 마크를 읽을 수 있는 크기로 배치한다.
- 앱 UI의 한글 제목은 Pretendard를 쓴다. Archivo Black는 워드마크·브랜드 헤딩에만 쓰고, 한글 글리프는 적절한 한글 폴백으로 표시한다.
- `ArchivoBlack-Regular.ttf`의 CSS weight는 400이다. 파일명에 Black이 있다고 900 합성 굵기를 중복 적용하지 않는다.
- 브랜드 Yellow는 CTA·선택·핵심 진행 표시의 소면적에 사용한다. 앱 전체를 노란 바탕으로 만들지 않는다.
- 서비스명은 Roxlogy/록솔로지, 워드마크는 ROXLOGY다. HYROX를 앱 이름·서브타이틀·패키지명으로 사용하거나 공식 로고를 모방하지 않는다.
- 기존 랜딩 사전의 태그라인을 재사용한다. 타 프로젝트 자산·임시 영문 타이틀·시안용 계정 이름을 제품 화면에 남기지 않는다.

### 2.2 문구와 데이터

제목은 사용자의 과업을, 보조 설명은 범위·조건을, 버튼은 다음 행동을 설명한다. 빈 화면에는 원인과 가능한 다음 행동을 함께 둔다. 성공을 확정하기 전에는 “완료”를 표시하지 않는다.

화면에 실제 계좌·금액·인원·기록·권한을 하드코딩하지 않는다. 랜딩의 `makeLandingDemo()`는 기존 데모 전용 예외다. 데모는 데모로 인식할 수 있어야 하며, 이를 로그인한 사용자의 대시보드나 회계에 재사용하지 않는다. 캡처와 문서 예시는 합성 데이터 또는 가림 처리한 데이터로 만든다.

## 3. 색상·타이포·공간 체계

`text-background`를 채움 버튼의 글자색으로 재사용하지 않는다. 노란 버튼에는 `text-on-accent`, 의미 색 버튼에는 그 테마의 `text-on-solid`를 쓴다. 채움의 밝기가 바뀌면 실제 조합을 다시 확인한다. 성공/실패/선택은 색 외에 텍스트·아이콘·형태로도 표시한다.

다크는 PFT 라이브보드·주요 레이스 결과·랜딩 데모처럼 목적이 있는 영역에 `data-theme="dark"`로 한정한다. 인증 브랜드 패널과 외부 공유물은 별도 차콜 `#222930` 계열이다. 앱 전역 테마 전환 설정을 새로 만든 것으로 간주하지 않는다.

기존 검증 기록의 대비 계산은 특정 기본 조합의 결과다. 전체 화면·모든 disabled 상태·차트가 접근성 기준을 충족했다는 증거는 아니다. 준수 목표는 일반 텍스트 4.5:1, 큰 텍스트와 조작 식별 요소 3:1이며 실제 인접 배경에서 확인한다. 얇은 장식 구분선과 입력을 구분하는 필수 경계는 같은 기준으로 취급하지 않는다.

### 3.2 타이포그래피

| 역할 | 현재 대표값 / 준수 기준 |
| --- | --- |
| 워드마크 | Archivo Black 400, 앱 내 대표 18px, 자간 `.025em`. 화면별 기존 크기 유지 |
| 앱 페이지 제목 | 데스크톱 30px / 1.4 / 750, 모바일 25px. 공개 랜딩·상태 화면은 별도 크기 |
| 섹션·카드 제목 | Pretendard 17–20px를 기본 위계로 사용. 작은 하위 제목과 구분 |
| 본문·입력 | 본문 14–16px 맥락별 사용, 모바일 폼 입력 최소 16px |
| 보조·표 머리글 | 12–13px. 중요한 안내를 가는 10px 글자에 의존하지 않음 |
| KPI | 대시보드 대표 30px → 중간 폭 26px → 모바일 25px, 회계 28px |
| 결과 | 레이스 주요 결과 48px → 모바일 40px. 타이머는 길이가 바뀌어도 레이아웃 고정 |
| 숫자·금액·기록·날짜 | `tabular-nums` 또는 기존 `.tabular`. 금액 우측 정렬, 단위를 값과 구분 |

긴 이름과 스페인어 문구는 줄바꿈을 허용한다. 목록에서 말줄임하더라도 상세 화면에서 전체 내용을 읽을 수 있어야 한다. 핵심 금액·시간·오류 원인은 말줄임하지 않는다. 숫자 자릿수를 맞추기 위해 단위나 부호를 제거하지 않는다.

### 3.3 공간·표면·레이어

현재 `renewal.css`의 주요 패널은 반경 14px, 선 1px, 패딩 24px/모바일 20px다. 폼 래퍼는 데스크톱 28px, 상태 카드는 20px 반경, Dialog는 18px/모바일 시트 상단 20px다. 기존 세부 컴포넌트의 8–12px 반경을 전부 강제로 14px로 만들지 않는다.

준수 기준은 4px 기반 간격(4·8·12·16·20·24·32·40·48)으로 관련성과 위계를 표현하는 것이다. 폼의 라벨·입력·힌트는 한 묶음, 서로 다른 섹션은 더 큰 간격을 쓴다. 일반 패널은 선으로 구분하고 강한 그림자는 모달 등 떠 있는 요소에 제한한다.

레이어의 현재 관계는 일반 콘텐츠 → 고정 저장 바(`z-30`) → 하단 탭바(`z-40`) → 사이드바(`z-index:45`) → Dialog(`z-50`)다. 화면마다 임의의 큰 z-index를 추가하지 않는다. 중첩 Dialog의 완전한 스택 관리는 현행 컴포넌트가 보장한다고 가정하지 않는다. 한 번에 하나를 열거나 후속 구현에서 명시적으로 처리한다.

## 4. 공통 레이아웃과 반응형

### 4.1 앱 셸

구현: `web/components/global-nav.tsx`, `web/components/mobile-tabbar.tsx`, `web/lib/nav.ts`, `web/app/renewal.css`.

데스크톱은 248px 사이드바와 74px 헤더, 본문이다. 현재 영역·검색·언어·알림·프로필은 헤더에 두고, 사이드바는 활동/훈련·레이스·커뮤니티 관련 진입점을 그룹화한다. 관리자 메뉴는 기존 관리자 조건을 따른다. 검색은 실제 검색 화면 링크이며 동작하지 않는 검색 입력처럼 꾸미지 않는다.

공개 화면은 공개 메뉴와 로그인 동선을 사용한다. 로그인된 크루 방문자는 앱 셸과 하단 탭바를 재사용한다. 랜딩·인증·독립 보드는 각 목적에 맞는 별도 셸이다. 본문 바로가기와 실제 `main-content` 대상의 연결을 유지한다.

### 4.2 현재 구현의 전환점

수치는 **브라우저 뷰포트 CSS px**다. 사이드바가 있는 화면의 본문 폭과 혼동하지 않는다. `max-width`는 해당 값 이하, `min-width`는 해당 값 이상이다.

| 조건 | 현재 코드의 변화 |
| --- | --- |
| 1500px 이상 | 앱 본문 좌우 패딩 48px |
| 1200px 초과 기본 | 본문 `32px 36px 60px`(위·좌우·아래), 기본 콘텐츠 최대 1600px |
| 1200px 이하 | 본문 `28px 24px 60px`, 검색 라벨 축약, 회계 보조 열 290px, 선수 카드 2열 |
| 1100px 이하 | 회계 본문/보조 영역 스택, 보조 카드 2열·폼 전체 폭. 스태프 상단 1열 |
| 1050px 이하 | 대시보드 KPI 2열·본문/분석 스택, 러닝 요약 스택, 설정 좌측 목차 숨김 |
| 767px 이하 | 사이드바 숨김, 60px 헤더·모바일 서랍·하단 탭바, 본문 좌우 16px |
| 600px 이하 | 회계 보조 카드 1열, 스태프 선수 카드 1열 |
| 1200px 이상 | 보드 3열: `220px minmax(0,1.2fr) minmax(300px,1fr)` |
| 1700px 이상 | 보드 참가자 260px·순위 열 최소 380px로 확장 |
| 1400px 이상 | 프로그램·운동 카탈로그 3열 |

모바일 앱 본문 하단은 `calc(96px + env(safe-area-inset-bottom))` 여백을 둔다. 공개 셸은 하단 탭 유무에 따라 다르다. 컴포넌트 자체 최대 폭이 있는 폼·내 레이스 계획은 공통 최대 폭까지 억지로 늘리지 않는다.

### 4.3 모바일과 WebView

웹 탭 순서는 **세션·훈련·레이스·크루·피드**다. 훈련·레이스는 하위 메뉴 시트를 열고 나머지는 해당 경로로 이동한다. 시트를 여는 버튼에는 펼침 상태와 dialog 관계를 제공한다. 경로가 바뀌면 기존 시트가 닫힌 것으로 처리한다.

실제 `roxNative()?.openWatch`가 있을 때만 **세션·훈련·Watch·레이스·크루·피드** 6개가 된다. Watch는 네이티브 브리지를 호출한다. 웹 가짜 Watch 페이지, 사용자 에이전트 문자열만으로 판단한 탭, 네이티브/웹 중복 탭바를 만들지 않는다.

준수 기준:

- 터치 표적은 44×44px 이상, 주요 저장·입력은 48px를 목표로 한다. 작은 아이콘의 시각 크기와 클릭 영역은 분리할 수 있다. 현재 모든 보조 버튼이 이 조건을 충족하는 것은 아니다(§11).
- 서랍은 현재 288px, 최대 `100vw - 24px`, 높이 `100dvh`다. 본문 스크롤과 독립하고 닫은 뒤 호출 버튼으로 포커스가 돌아와야 한다.
- 하단 탭·고정 저장·프로그램 도구막대는 safe area를 포함하며 마지막 입력/행을 가리지 않는다. 현재 프로그램 하단 오프셋 62px와 세션 64px는 실제 탭 높이와 실기기에서 대조한다.
- 입력 키보드가 열린 상태에서 포커스 입력·오류·저장 버튼에 내부 스크롤로 접근할 수 있어야 한다. `dvh` 선언만으로 실기기 검증을 대체하지 않는다.
- 페이지 전체의 가로 넘침은 허용하지 않는다. 표·필터·크루 탭처럼 의미가 있는 영역만 내부 스크롤을 허용한다.
- 회전·200% 확대·긴 번역에도 버튼이 겹치지 않아야 한다. hover로만 드러나는 필수 행동을 만들지 않는다.

## 5. 컴포넌트별 구현 기준

### 5.1 제목·카드·요약

페이지는 제목과 목적 → 범위/상태와 주요 행동 → 데이터/입력 → 보조 정보 순서로 읽히게 한다. 한 영역에서 가장 중요한 CTA를 하나로 정하고 부차 행동은 선형/텍스트 버튼으로 구분한다. 삭제·마감 등 위험 행동은 저장·출발 버튼과 공간적으로 구분한다.

카드 제목은 `h2`/`h3` 등 문서 위계를 따른다. 전체 카드 링크 안에 다른 버튼을 중첩하지 않는다. 필터를 바꿨을 때 KPI의 집계 범위도 바뀌는지 문구로 명시한다. 값이 없는 상태와 실제 0은 구분한다.

### 5.2 버튼·링크·탭 상태

| 상태 | 시각·행동 기준 |
| --- | --- |
| 기본 | 주요 CTA `accent/on-accent`, 보조는 `control/line/foreground`, 위험은 danger 계열 |
| hover / pressed | 기존 색·경계를 유지하면서 구분. 위치가 움직이거나 텍스트 폭이 튀지 않음 |
| focus-visible | 현재 파랑 `#2D7DFF` 2px outline, 일반 offset 2px·입력 0. 컨테이너에서 잘리지 않음 |
| 현재 위치 / 선택 | 색 + 채움/선/굵기 + 적절한 `aria-current` 또는 선택 상태 |
| disabled | 실제 비활성 속성과 이유를 함께 제공. 권한이 없는 파괴적 기능을 회색 버튼으로 모두 노출하지 않음 |
| 진행 중 | 행동의 진행 문구·상태를 제공하고 중복 제출 방지. 버튼 폭과 폼 입력 유지 |
| 성공 | 서버 응답 뒤 해당 영역에 성공 안내. 복사 완료는 실제 복사 성공 뒤에만 표시 |
| 실패 | 작업 대상 가까이에 원인/재시도 안내, 입력값 보존. 실패를 빈 목록이나 성공으로 바꾸지 않음 |

이 표는 모든 기존 버튼이 각 상태를 이미 제공한다는 뜻이 아니라 검수 계약이다. MCP의 복사 실패 처리 등 확인된 차이는 §11에 기록한다.

### 5.3 폼

라벨은 플레이스홀더와 별도로 항상 읽을 수 있어야 한다. 필수 여부·단위·형식 힌트를 입력 옆에 둔다. 오류는 해당 입력과 연결하고 텍스트로 설명한다. 범위/숫자 입력은 기존 도메인 검증을 유지한다.

저장 전후와 실패 상태의 레이아웃을 함께 설계한다. 편집은 실제 기존 값으로 시작하고 취소는 기존 복귀 경로를 따른다. 숫자·일시를 보기 좋게 바꾸면서 전송 단위(ms, 원, 날짜)를 바꾸지 않는다. 모바일 숫자 키패드를 유도하더라도 음수·소수·시간 형식의 유효 입력을 막지 않는다.

### 5.4 목록·표·필터

행의 제목, 핵심 수치, 상태, 보조 정보의 우선순위를 유지한다. 이름은 좌측, 금액·시간은 우측/일관된 열, 단위는 머리글 또는 값 옆에 둔다. 전체 행 이동은 기존 `RowLink`를 재사용하고 행별 프리페치 폭증을 유발하지 않는다.

검색 결과 없음과 데이터가 아직 없음은 다른 빈 상태다. 필터 초기화 경로를 제공한다. 확장 행은 확장 여부를 나타내고, 합산 행과 원본 행을 구분한다. 모바일에서 열을 숨길 경우 같은 정보에 접근할 상세/펼침 경로가 있어야 한다. 단순 삭제로 공간을 확보하지 않는다.

### 5.5 차트·진행률·배지

기존 `chart-frame.tsx`, `charts.tsx`, 종목별 색 매핑을 사용한다. 단위·기간·범례를 유지하고 툴팁 배경·글자를 토큰에 맞춘다. 런/스테이션 등 데이터 의미가 있는 색을 장식 목적으로 재배정하지 않는다. 낮은 대비의 선은 굵기·마커·텍스트로 보완한다.

데이터 부족은 0점·0초로 채우지 않는다. 애니메이션은 핵심 값을 늦게 보여주지 않고 reduced-motion에서 제거한다. 색을 구분하기 어려워도 상태명·범례·수치로 의미를 파악할 수 있어야 한다.

### 5.6 자체 Dialog·Sheet

구현은 `web/components/ui/dialog.tsx`를 사용한다. shadcn Dialog/Sheet를 추가해 포커스·레이어 동작을 이원화하지 않는다. 호출부에서 `label`, 번역된 `closeLabel`, `onClose`, 적절한 variant를 전달한다.

| variant | 용도 | 현재 반응형 |
| --- | --- | --- |
| `center` | 짧은 확인·선택 | 중앙 유지, 내부 스크롤 |
| `scroll` | 긴 폼·설정 | 데스크톱 중앙/스크롤, 모바일 아래 정렬 |
| `sheet` | 모바일 하위 내비게이션 | `md` 미만에서 하단 표시 |
| 서랍 확장 | 모바일 전체 메뉴 | `rx-drawer`의 좌측 288px·100dvh 예외 |

현재 공통 기능은 body portal, `role="dialog"`, `aria-modal`, Tab/Shift+Tab trap, Escape/배경/닫기 버튼, body 스크롤 잠금, 배경 inert, 포커스 복귀다. 기본 패널 최대 높이는 85dvh다. 모바일 시트 하단에 safe area를 더한다.

검수 시 실제 첫 포커스 위치·마지막 컨트롤에서의 순환·닫힌 뒤 복귀를 확인한다. 명시적 닫기 버튼이 DOM 앞에 있으므로 중요한 입력에 자동 포커스된다고 가정하지 않는다. 파괴적 확인에서 기본 포커스가 실행 버튼이 되지 않도록 한다. 기존 `window.confirm` 사용처는 이 문서로 자동 대체된 것이 아니다.

## 6. 전체 화면별 상세 지침

아래 D01–D22는 디자인 검수 단위다. §12의 실제 페이지 전부가 한 단위에 연결된다. 각 단위는 공통 상태 기준(§7), 다국어(§9), 완료 기준(§10)을 함께 적용한다. 아래 “확인”은 수행해야 할 검수 항목이며 기존 완료 증거가 아니다.

### D01. 마케팅 랜딩 `/`

소스: `web/app/page.tsx`, `web/components/landing-crew-ticker.tsx`, `web/lib/landing-demo.ts`.

- 구성: 원본 마크·워드마크·언어·가입/로그인 → 히어로 카피·CTA → 기록 데모와 스플릿 → 기능 3개 → 공개 크루 티커 및 기존 후속 CTA.
- 데모의 런/스테이션 구분과 주요 결과를 먼저 읽히게 한다. 실제 공개 크루의 이름·지역·인원은 공개 조회를 사용한다. 없는 크루를 목업으로 채우지 않는다.
- 모바일은 기존 섹션 순서로 쌓고 가입 CTA와 언어 선택을 유지한다. 티커 hover 정지·reduced-motion 정지를 보존한다. 포커스로 읽는 사용자의 정지 가능성도 후속 검수한다.
- 확인: ko/en/es 긴 히어로, 크루 0개, 긴 크루명, CTA 이동, `?code=` 콜백 복귀, 데모임을 구별할 수 있는 문구. 데모 숫자를 실제 기록으로 오해하게 만들지 않는다.

### D02. 로그인·가입 `/login`, `/signup`

소스: `web/components/auth-form.tsx`, 각 `page.tsx`.

- 데스크톱은 차콜 브랜드 패널/밝은 인증 폼 2단. 모바일은 폼을 먼저, 브랜드 설명을 뒤에 배치한다. 언어 선택은 폼 상단에서 접근한다.
- Google 버튼·이메일·비밀번호·표시 전환·유지 선택·로그인/가입 전환·기존 안내를 유지한다. 폼 제목은 현재 모드를 분명히 한다.
- 확인: 빈 제출, 잘못된 인증, 전송 중, Google 실패, 가입 안내, 긴 오류, 키보드 열린 상태의 제출. 오류가 생겨도 입력을 잃거나 브랜드 패널에 가려지지 않는다.
- One Tap은 §8 정책을 따른다. Google 인증 동작·nonce·리디렉트 규칙은 스타일 변경 대상이 아니다.

### D03. 네이티브 인증 `/auth/native`

소스: `web/app/auth/native/page.tsx`.

- 원본 마크·연결 중 상태·실패 시 복귀 경로를 간결한 상태 패널에 둔다. 일반 가입 화면처럼 보이게 하지 않는다.
- 현재 hash 즉시 제거 → 세션 수립 → 검증된 내부 경로 이동 계약을 유지한다. 토큰을 DOM·오류 문구·로그·캡처에 출력하지 않는다.
- 확인: 정상 전달, hash 없음/잘못된 값, 세션 수립 실패, 외부 next 거절, 뒤로 가기·새로고침. 실제 WebView 검증은 별도 필요하다.

### D04. 대시보드 `/dashboard`

- 구성: 제목/주 액션 → 실제 집계 KPI 4개 → 최신 레이스 강조 카드 → 최근 기록과 오늘 일정 → 분석 카드.
- 데스크톱 기록은 좌측, 오늘 일정은 우측. 1050px 이하에서 오늘 일정이 먼저 읽히는 스택과 KPI 2열을 유지한다.
- 최신 레이스가 없거나 분석할 기록이 부족하면 관련 생성/기록 동선과 상태를 표시한다. 없는 기록을 샘플 성적으로 대신하지 않는다.
- 확인: 신규 계정, 기록만/일정만 있는 계정, 긴 대회명, 큰 기록 숫자, 카드의 실제 목적지, 사용자 시간대의 “오늘”.

### D05. 세션 목록·비교·상세·생성·수정

### D20. 프로필 설정·MCP·푸시 `/settings/profile`

소스: `profile-form.tsx`, `linked-accounts.tsx`, `settings-nav.tsx`, `mcp-connect.tsx`, `notification-settings.tsx`, `ui/settings-ui.tsx`.

구성: 프로필 → 계정/로그인 수단/앱 다운로드 → 외부 기록 연결·MCP → 알림 → 로그아웃. 큰 화면은 좌측 목차와 우측 카드, 모바일은 한 열과 섹션 칩이다. 현행 768–1050px에서 목차·칩의 표시 조건이 어긋나는 점은 §11의 후속 항목이다.

**MCP 카드**는 제목·읽기/쓰기 상태 → 설명 → 엔드포인트 복사 → 토큰 미발급/마스킹·표시/복사 → 연결 안내 → 발급/재발급·폐기·쓰기 권한의 기존 행동 순서와 의미를 유지한다.

- 미발급을 빈 문자열 입력처럼 보이게 하지 않는다. 토큰은 기본 마스킹, 표시/숨기기와 복사는 구분한다.
- 재발급·폐기·쓰기 허용은 기존 확인 과정을 유지하고, 진행·실패·성공을 해당 카드에서 보여준다. 외부 클라이언트 연결이 확인되지 않았는데 “연결 완료”로 표시하지 않는다.
- 긴 endpoint/token은 카드 내부에서 처리하고 실제 토큰을 문서·분석 이벤트·스크린샷에 남기지 않는다.
- 확인: 미발급/발급됨, 마스킹/표시, 복사 성공/실패, 재발급 취소/실패, 폐기, 읽기/쓰기 전환, 모바일 줄바꿈.

**알림 카드**는 환경 지원/설정 여부 → 기기 푸시 활성화/해제·테스트 → 종류별 선호·WOD 시간 등 기존 설정 순서다. 브라우저 Web Push와 네이티브 FCM 상태를 같은 성공 상태로 뭉개지 않는다.

- 미지원, 권한 거절, 비활성, 활성, 네이티브 준비 중, 요청 중, 테스트 결과를 구별한다. 권한 요청은 사용자가 해당 행동을 했을 때 시작한다.
- 푸시가 꺼져 있어도 종류별 선호를 설정할 수 있는 기존 정책을 유지한다. 전달 권한과 서버 선호를 같은 토글로 대체하지 않는다.
- 확인: denied/unsupported, 테스트 발송 대상 없음, 다중 기기, WOD 시각/시간대, 권한 요청 후 복귀. 선호 저장 실패의 롤백/안내는 현재 보완이 필요하다(§11).

현재 렌더 기준은 1200×630, 배경 `#222930`, 글자 `#F4F4F2`, 보조 `#ACB8C1`, 강조 `#FFD500`, 좌우 64px·상하 52px 안전 여백이다. 제목 55px, 보조 23–26px, 숫자 48px다. 제목/부제/상세는 각각 36/46/40 Unicode 코드포인트로 제한하고 전체 제목은 본문/메타데이터에서 읽는다.

공유물은 쿠키 언어로 개인화하지 않는다. 사용자 작성 제목은 유지하고 라벨은 영어, 모임 시각은 KST를 명시한다. 세션·프로그램·레이스별 OG는 추가하지 않는다. 해당 기록 공유는 canvas 카드가 담당한다.

공개 조회는 `web/lib/og/public-data.ts`의 쿠키 없는 익명 클라이언트와 공개 RPC를 따른다. 비공개·멤버 전용·취소·없는 항목·slug 불일치·조회 실패는 동일한 일반 브랜드 PNG를 사용한다. 멤버 이름·계좌·개인 토큰·접근 불가 이유를 이미지에 넣지 않는다.

동적 폰트는 저장소 TTF 버퍼를 서버 프로세스에서 재사용한다. 웹 Pretendard 92개 CSS 서브셋을 이미지 렌더 폰트로 직접 전달하지 않는다. OG용 한글 폰트를 일반 웹 페이지에 추가 로드하지 않는다. 공개 경계·no-store·3초 조회 제한과 외부 공유 플랫폼 캐시의 한계는 [상세 구현 기록](DESIGN_GAPS_IMPLEMENTATION.md)을 따른다.

### 8.3 One Tap 정책

소스: `web/components/google-one-tap.tsx`, `crew-header.tsx`, `auth-form.tsx`.

현재 노출 위치는 로그아웃한 크루 페이지와 로그인/가입 페이지다. `use_fedcm_for_prompt: true`, `cancel_on_tap_outside: false`를 유지한다. 마운트당 초기화/프롬프트 요청은 한 번이며, 앱 타이머로 재노출하거나 cooldown을 초기화하지 않는다.

FedCM 프롬프트는 브라우저, 레거시 폴백은 Google SDK가 그린다. 자체 브랜드 카드로 복제하거나 크기·위치·z-index를 통제할 수 있다고 가정하지 않는다. 클라이언트 ID가 없으면 렌더하지 않으며, SDK/nonce/교환 실패 시 일반 이메일·Google 버튼 경로를 유지한다.

실제 FedCM과 레거시가 표시되는 조건에서 각각 확인한다. 레거시의 데스크톱/모바일 겹침 캡처가 없으면 UI가 문제없다고 확정하지 않는다. 계정 사진·이메일이 있는 캡처는 가림 처리한다. 임의의 재노출 일수 정책을 문서나 코드에 추가하지 않는다.

## 9. 다국어·접근성·기술 경계

### 9.1 ko / en / es

사전은 `web/lib/i18n/dictionaries/ko.ts`, `en.ts`, `es.ts`다. 새 사용자 문구는 세 언어에 함께 추가하고 `getT`/`useI18n`의 기존 키를 사용한다. 버튼·오류·권한·loading·aria-label·복사 성공도 번역 범위다. 제품 고유명·단위·사용자 작성 이름까지 임의 번역하지 않는다.

날짜/시간은 `web/lib/format.ts`와 실제 locale/timezone을 따른다. “오늘”은 사용자/서버의 기존 시간대 계약으로 판정한다. 회계는 실제 원화 의미를 유지하고 언어가 바뀌었다고 금액을 환산하지 않는다. 시간(ms)·거리·반복 수·통화 기호의 의미를 번역 문자열에 맞추다 바꾸지 않는다.

언어 전환 뒤 경로·선택 상태·숫자 의미가 유지되는지 확인한다. 특히 긴 es 버튼, 한글 공백 없는 이름, 영문 긴 endpoint, 서로 다른 날짜 표기를 검수한다. 기존 코드에 남은 영어 보조 라벨은 번역 누락 여부를 별도로 판단하며 “en/es 전체 시각 검증 완료”로 표시하지 않는다.

### 9.2 접근성 완료 조건

키보드만으로 메뉴·탭·폼·표 행동·Dialog를 완료할 수 있어야 한다. 제목 위계, 입력 라벨, 상태 안내, 의미 있는 이미지 대체 텍스트, 장식 아이콘 숨김, 보이는 포커스를 확인한다. 자동 진행 숫자 전체를 매 프레임 읽게 하는 과도한 live region은 피한다.

색 대비·확대·reduced-motion·스크린리더 확인은 각 화면의 실제 데이터로 수행한다. 서버 렌더 HTML에 aria 속성이 존재한다는 사실만으로 이 검수를 통과시키지 않는다.

### 9.3 구현 경계

- 스타일은 `globals.css`의 의미 토큰과 `renewal.css`의 레이아웃, 기존 컴포넌트의 구조를 우선 사용한다. 임의 hex·전역 선택자·`!important`를 추가할 때 적용 범위를 확인한다.
- Next.js 서버 컴포넌트와 기존 Suspense/로딩 구조를 유지한다. 레이아웃 편의를 위해 루트에서 쿠키를 읽거나 전체 페이지를 client component로 바꾸지 않는다.
- 기존 Auth·Proxy·RLS·서버 조회·저장·회계 집계·PFT 시각/재전송 계약을 보존한다. 디자인 작업을 이유로 DB 스키마·공개 범위를 변경하지 않는다.
- 실제 저장 응답의 오류를 확인하고, 스타일 변경과 별개로 오류를 무시하는 기존 경로가 발견되면 보완 항목으로 추적한다.
- 테스트 합성 데이터는 `web/tests/fixtures/`에만 둔다. 앱 코드에 fixture를 import하지 않는다. 원본 자산·라이선스를 유지하며 불필요한 UI 프레임워크를 추가하지 않는다.
